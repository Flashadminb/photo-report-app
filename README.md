# ระบบถ่ายรูปอัพเดทงาน / Field Photo Report

ของจริงที่ทำงานได้ ตามแบบใน Claude Design (`Photo Report App.dc.html`)
สร้างเป็น **Google Apps Script web app** ที่อ่าน–เขียนไฟล์ Google Sheets เดิมของงานโดยตรง

## โครงระบบ

หน้าจออยู่บน **GitHub Pages** · หลังบ้านอยู่บน **Apps Script** · ข้อมูลอยู่ใน **Google Sheets + Drive**

```
พนักงาน ── เปิดแอพ ──▶ GitHub Pages (docs/)         ไฟล์นิ่ง + Service Worker
                            │                        เปิดได้ทันที แม้ไม่มีสัญญาณ
                            │  fetch POST {fn,args}
                            ▼
                       Apps Script doPost            ตรวจเงื่อนไข + สิทธิ์
                            │
                            ▼
                  Google Sheets (MASTER / DATA) + Drive (รูป)
```

**ทำไมต้องแยก 2 ที่** — GitHub Pages เสิร์ฟไฟล์นิ่งเท่านั้น เขียนชีทเองไม่ได้
ส่วน Apps Script เขียนชีทได้ แต่รันแอพในกรอบ sandbox จึงติดตั้งเป็นแอพ (PWA) ไม่ได้และ Service Worker ก็ใช้ไม่ได้
แยกกันแล้วได้ข้อดีทั้งสองฝั่ง

> `apps-script/app.html` กับ `admin.html` ยังเสิร์ฟจาก Apps Script ได้อยู่ (`/exec`) เก็บไว้เป็นทางสำรอง
> `rpc()` ตรวจเองว่ารันอยู่ที่ไหน — มี `google.script.run` ก็ใช้ตัวนั้น ไม่มีก็ยิง `fetch`

## ติดตั้ง (ทำครั้งเดียว ~10 นาที)

1. เปิดไฟล์ **MASTER** → เมนู **ส่วนขยาย › Apps Script**
2. ลบไฟล์ `Code.gs` ที่ Google สร้างให้ทิ้ง แล้วสร้างไฟล์ตามนี้ (ก๊อปเนื้อหาจากโฟลเดอร์ `apps-script/`)

   | ชนิด | ชื่อไฟล์ใน editor |
   | --- | --- |
   | Script | `Config`, `Master`, `Records`, `Photos`, `Api`, `Setup` |
   | HTML | `app`, `admin`, `css`, `js-common`, `js-app`, `js-admin` |

   *(ถ้าใช้ [clasp](https://github.com/google/clasp) ก็ `clasp push` ได้เลย — `appsscript.json` เตรียมไว้แล้ว)*
3. ตั้ง timezone เป็น `Asia/Bangkok` (ไฟล์ `appsscript.json` ตั้งไว้ให้แล้ว — ถ้าก๊อปมือ ให้ตั้งใน **โครงการ › การตั้งค่า**)
4. รันฟังก์ชัน **`checkSetup`** หนึ่งครั้ง → กด **Review permissions** → อนุญาต
   ผลลัพธ์ควรขึ้น ✓ ทุกบรรทัด ถ้ามี ✗ แปลว่าหัวตารางในชีทไม่ตรง ให้แก้ชีทหรือแก้ `CFG.COL`
5. รัน **`installOpenReturnsFormula`** หนึ่งครั้ง (วางสูตร FILTER ในชีท "ค้างคืน" แทนแถวคำอธิบาย)
6. **Deploy › New deployment › Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** ← จำเป็น ถ้าพนักงานหน้างานไม่มีบัญชี Google
7. ก๊อป URL ที่ได้ ส่งให้พนักงาน (`/exec`) และส่งให้แอดมิน (`/exec?page=admin`)

**บนมือถือ:** เปิด URL ใน Chrome/Safari → เมนู → *เพิ่มไปยังหน้าจอโฮม* จะได้ไอคอนเหมือนแอพ

## ระบบทำงานยังไง

### ฝั่งพนักงาน
```
ใส่รหัสพนักงาน 6 หลัก   →  ดึงชื่อ/แผนก/กะ จากชีท "พนักงาน"
เลือกหัวข้อ              →  มาจากชีท "หัวข้อสำรวจ" (ปิดหัวข้อ = หายจากแอพทันที)
เลือกรหัสเครื่อง          →  มาจากชีท "เครื่อง" กรองเฉพาะ "พร้อมใช้" + แผนกตัวเอง
ถ่ายรูปทีละจุด            →  จำนวนจุดและคำแนะนำมาจากชีท "ช่องถ่ายรูป"
เลือกปกติ / มีปัญหา       →  มีปัญหาต้องกรอกอาการ + ถ่ายรูปจุดที่เสีย
ตรวจทาน → ส่ง            →  เขียนแถวลงชีท "บันทึก" + "รูปภาพ" + อัปโหลดรูปขึ้น Drive
```
รายการที่ "เบิก" จะค้างอยู่ในหน้าหลักจนกดปุ่ม **คืน** ซึ่งจะเขียนอีกแถวหนึ่งพร้อมใส่
รหัสรายการเบิกในคอลัมน์ *อ้างอิงรายการเบิก* — ตรงกับสูตรในชีท "ค้างคืน" ที่มีอยู่เดิม

### เงื่อนไขในชีท "เงื่อนไข" บังคับใช้จริง

| รหัสเงื่อนไข | ผลเมื่อเปิด |
| --- | --- |
| `live` | ซ่อนปุ่มเลือกจากคลังภาพ เปิดกล้องอย่างเดียว (`capture=environment`) |
| `gps` | ไม่มีพิกัด = ปุ่มส่งไม่ทำงาน และเซิร์ฟเวอร์ปฏิเสธ |
| `stamp` | ประทับวันเวลา + พิกัด + รหัสเครื่อง + ชื่อผู้ถ่าย ลงบนภาพจริง (วาดด้วย canvas ก่อนอัปโหลด) |
| `shift` | ถ่ายนอกกะยังส่งได้ แต่ต่อท้ายหมายเหตุว่า `[นอกกะ]` |
| `issue` | เลือก "มีปัญหา" ต้องมีทั้งข้อความอาการและรูปช่อง "จุดที่มีปัญหา" |
| `count` | ใช้ตัวนับจำนวนแทนการเลือกรหัสทีละเครื่อง (แบบ IDATA) |
| `draft` | เปิดคิวออฟไลน์ |

ทุกข้อถูกตรวจ **ทั้งฝั่งมือถือและฝั่งเซิร์ฟเวอร์** — แก้ HTML ในเครื่องแล้วยิงตรงก็ยังไม่ผ่าน

### แอพหน้างานไม่เก็บรูปไว้ในเครื่อง

- ระหว่างถ่ายจะเห็นตัวอย่างรูปได้ตามปกติ (หน้ากล้อง + หน้าตรวจทาน)
- **กดส่งสำเร็จปุ๊บ รูปถูกล้างออกจากหน่วยความจำทันที** และหน้า "ส่งแล้ว" ไม่มีปุ่มเปิดดูรูปย้อนหลัง
- ดูรูปย้อนหลังได้ที่เว็บแอดมินเท่านั้น
- ข้อยกเว้นเดียว: ถ้าส่งไม่ผ่าน (ไม่มีสัญญาณ) รูปจะถูกพักไว้ในเครื่องจนกว่าจะส่งได้ แล้วลบทิ้งเอง

### แอพเปิดเร็ว

- เปิดครั้งที่ 2 เป็นต้นไปจะขึ้นหน้าหลัก **ทันที** จากข้อมูลที่จำไว้ในเครื่อง แล้วค่อยดึงของจริงมาทับเงียบ ๆ
  (จำเฉพาะทะเบียน/หัวข้อ/รายการค้างคืน — ไม่มีรูป)
- ฟอนต์โหลดผ่าน `<link>` + `preconnect` ใน `<head>` และตัดน้ำหนักที่ไม่ได้ใช้ออก (8 ไฟล์ → 5 ไฟล์)
- ไม่มีสัญญาณก็ยังเปิดใช้หน้าหลักได้ ไม่เด้งกลับหน้าล็อกอิน

### ออฟไลน์
ไม่มีสัญญาณ → รายการ (รวมรูป) ถูกเก็บใน IndexedDB ของเครื่อง
พอสัญญาณกลับมาจะส่งให้เองอัตโนมัติ หรือกด "ส่งทั้งหมดตอนนี้" ในหน้าคิวก็ได้
มีรหัส `clientId` กันส่งซ้ำ ถ้าเน็ตหลุดกลางทางแล้วลองใหม่

### ย้ายข้อมูลออกไปเก็บที่อื่น แล้วล้างชีท

ถ้าใช้ชีทเป็นแค่ที่พักข้อมูล แล้วก๊อปไปลงระบบขององค์กรเป็นรอบ ๆ ทำได้ครับ แต่ต้องครบ 3 อย่าง
ไม่งั้นรูปจะยังกินพื้นที่ Drive อยู่ทั้งที่ลบแถวในชีทไปแล้ว

1. ลบแถวในชีท **บันทึก**
2. ลบแถวในชีท **รูปภาพ**
3. **ลบไฟล์รูปใน Drive + ล้างถังขยะ** ← ข้อที่คนลืม ลบแถวในชีทไม่ได้ลบไฟล์

ลบรูปได้ 2 ทาง: กด "ลบรูปชุดนี้" ทีละรายการในเว็บแอดมิน หรือเข้า Drive แล้วลบทั้งโฟลเดอร์วันที่
`รูปถ่ายหน้างาน/2026-08-06/` รวดเดียว (เร็วกว่าถ้าล้างเป็นเดือน) แล้วอย่าลืม **ล้างถังขยะ**

**กฎเหล็ก 3 ข้อ**

| ห้าม | เพราะ |
| --- | --- |
| ลบแถว **เบิก** ที่ยังไม่ถูกคืน | รายการนั้นจะหายจากหน้า "ค้างคืน" ในแอพ พนักงานกดคืนไม่ได้อีกเลย — ล้างเฉพาะคู่ที่ปิดครบ (เบิก + คืน) แล้วเท่านั้น |
| ลบแถวที่ 1 (หัวตาราง) หรือสูตรใน A2 ของชีท "ค้างคืน" | ระบบอ่านคอลัมน์ตามตำแหน่ง จะพังทันที |
| รัน `resetSequence` หลังล้างข้อมูล | เลขรหัสรายการจะย้อนกลับไปเริ่มใหม่ แล้วชนกับรหัสที่ export ไปแล้ว |

ตัวช่วย export: เว็บแอดมิน › แท็บ **ข้อมูล** › **ดาวน์โหลด CSV** (ได้เฉพาะข้อมูล ไม่รวมไฟล์รูป —
ถ้าต้องการรูปด้วยให้ดาวน์โหลดโฟลเดอร์จาก Drive แยก)

### รูปเก็บที่ไหน
```
โฟลเดอร์แม่/รูปถ่ายหน้างาน/2026-08-06/PP-20260806-1275/
    PP-20260806-1275-01-กุญแจ.jpg
    PP-20260806-1275-02-ด้านหน้า.jpg
    ...
```
รูปถูกย่อเหลือด้านยาว **1000px JPEG คุณภาพ 0.6** ก่อนอัปโหลด → ราว **80–120 KB/รูป**
(ตั้งค่าที่ `MAX_EDGE` / `JPEG_Q` ใน `js-common.html` อยากได้ละเอียดกว่านี้ก็ขยับขึ้นได้)
ลิงก์รายรูปลงชีท "รูปภาพ" ลิงก์โฟลเดอร์ลงชีท "บันทึก"

**พื้นที่ที่ใช้จริง** — Power Pallet 1 รอบ (เบิก 5 รูป + คืน 5 รูป) ≈ 1 MB
15 GB ฟรีของ Google แชร์กับ Gmail/Photos ด้วย ที่ 30 รอบ/วัน จะใช้ราว 0.6 GB/เดือน

> ⚠️ Google คิดพื้นที่จาก **เจ้าของไฟล์** ไม่ใช่เจ้าของโฟลเดอร์ — การแชร์โฟลเดอร์จากอีกบัญชีมาเก็บรูป
> **ไม่ช่วยลดโควตา** ถ้าจะย้ายภาระพื้นที่จริง ต้องให้บัญชีนั้นเป็นเจ้าของสคริปต์และ deploy เอง

**บทบาท:** `แอดมิน` = แก้ได้ทุกอย่าง · `หัวหน้างาน` = เข้าเว็บได้แต่ดูอย่างเดียว · `พนักงานหน้างาน` = ใช้แอพมือถืออย่างเดียว

รูปย่อในแท็บคลังรูปโหลดจาก `drive.google.com/thumbnail` ซึ่งต้องเป็นบัญชีที่มีสิทธิ์เห็นไฟล์
ถ้าแอดมินไม่ได้ล็อกอิน Google ด้วยบัญชีเจ้าของไฟล์ ให้แชร์โฟลเดอร์ `รูปถ่ายหน้างาน` ให้บัญชีนั้นก่อน

---

## ข้อควรรู้เรื่องความปลอดภัย

ระบบ deploy แบบ **Anyone** เพื่อให้พนักงานที่ไม่มีบัญชี Google ใช้ได้ ผลคือ:

- **รหัสพนักงานคือรหัสผ่าน** ใครรู้รหัส 6 หลักของคนอื่นก็ส่งงานแทนได้
- ใครที่ได้ URL ไป ก็ยิง API ได้ ถ้าเดารหัสพนักงานถูก
- หน้าล็อกอิน**ไม่แสดง**รหัสตัวอย่างโดยค่าเริ่มต้น (ถ้าอยากเปิดตอนสาธิต ให้รัน `enableDemoPins()` แล้วรัน `disableDemoPins()` ปิดกลับ)

ถ้ายอมรับความเสี่ยงนี้ไม่ได้ ทางเลือกคือเปลี่ยน deployment เป็น *Anyone with Google account*
แล้วให้พนักงานทุกคนล็อกอินด้วยบัญชีบริษัท — แต่จะช้าลงตอนใช้งานหน้างาน

ระบบ **ไม่ลบ**ข้อมูลอัตโนมัติ ปุ่ม "ลบรูปชุดนี้" ในเว็บแอดมินจะย้ายไฟล์ไปถังขยะ Drive (กู้คืนได้ 30 วัน)
แต่ **เก็บร่องรอยไว้ครบ** — แถวในชีท "บันทึก" และชีท "รูปภาพ" ยังอยู่ พร้อมลิงก์รูปเดิม ช่องถ่าย เวลา และพิกัด
เปลี่ยนแค่คอลัมน์ลิงก์โฟลเดอร์เป็น `ลบรูปแล้ว` ใช้เป็นหลักฐานย้อนหลังได้ว่าเคยถ่ายอะไรไว้บ้าง
(กดลิงก์แล้วจะไม่เห็นภาพหลังไฟล์ถูกล้างจากถังขยะ)

> ถังขยะ Drive **ยังกินโควตา** จนกว่าจะถูกลบถาวร (อัตโนมัติ 30 วัน หรือกดล้างเอง)
> ปุ่มลบรูปจึงยังไม่คืนพื้นที่ให้ทันที

## ดูแลรักษา

| อยากทำ | ทำยังไง |
| --- | --- |
| เพิ่มหัวข้อใหม่ | แอดมิน › หัวข้อสำรวจ › เพิ่ม แล้วไปตั้งช่องถ่ายรูป + เงื่อนไขในแท็บถัดไป |
| แก้ชีทเองแล้วอยากให้แอพเห็นทันที | เมนู "ระบบถ่ายรูป › ล้างแคชตั้งค่า" ในชีท MASTER (ปกติแคช 5 นาที) |
| ตรวจว่าทุกอย่างยังต่อกันถูก | รัน `checkSetup` |
| ย้ายไฟล์/โฟลเดอร์ | แก้ `apps-script/Config.gs` แล้ว deploy ใหม่ |

## โครงไฟล์

```
docs/                  ← GitHub Pages เสิร์ฟจากโฟลเดอร์นี้ (สร้างจาก build-web.ps1)
  index.html           แอพมือถือ
  admin.html           เว็บแอดมิน
  manifest.json        ชื่อ/ไอคอน/สี ตอนติดตั้งเป็นแอพ
  sw.js                Service Worker — แคชหน้าจอไว้เปิดตอนไม่มีเน็ต
  icons/               ไอคอนแอพ (สร้างจาก make-icons.ps1)

build-web.ps1          สร้าง docs/ จาก apps-script/
build-bundle.ps1       สร้าง bundle/ (3 ไฟล์สำหรับวางใน Apps Script)
make-icons.ps1         สร้างไอคอน

apps-script/           ← ซอร์สจริง แก้ที่นี่เสมอ
  appsscript.json      manifest (timezone, scopes, web app)
  Config.gs            ID ไฟล์ · ชื่อชีท · ลำดับคอลัมน์ · คำที่ใช้ในชีท
  Master.gs            อ่าน/เขียน MASTER + แคช
  Records.gs           อ่าน/เขียน DATA · รหัสรายการ · รายการค้างคืน
  Photos.gs            อัปโหลด/ลบรูปบน Drive
  Api.gs               doGet + ฟังก์ชันที่หน้าบ้านเรียก + ตรวจเงื่อนไขฝั่งเซิร์ฟเวอร์
  Setup.gs             checkSetup · installOpenReturnsFormula · เมนูในชีท
  css.html             โทเคนดีไซน์ Modernist (จากโปรเจกต์ Claude Design)
  app.html + js-app.html        แอพมือถือ
  admin.html + js-admin.html    เว็บแอดมิน
  js-common.html       rpc · toast · GPS · ย่อ+ประทับรูป · คิว IndexedDB

_design/               ไฟล์ต้นแบบที่ดึงมาจาก Claude Design (อ้างอิงอย่างเดียว)
_test/                 ชุดทดสอบหน้าจอในเบราว์เซอร์ ไม่ต้องอัปโหลด
```

### ทดสอบหน้าจอโดยไม่ต้อง deploy

```bash
powershell -ExecutionPolicy Bypass -File _test/build.ps1
```

แล้วเปิดเซิร์ฟเวอร์ทดสอบ

```bash
powershell -ExecutionPolicy Bypass -File _test/serve.ps1
```

เปิด `http://localhost:8777/app.html` (มือถือ) หรือ `/admin.html`
ข้อมูลเป็นของจำลองใน `_test/mock.js` ไม่แตะชีทจริง — รันใหม่ทุกครั้งที่แก้ไฟล์ใน `apps-script/`
